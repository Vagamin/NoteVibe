# Архитектура NoteVibe

## Стек и почему он

| Слой | Технология | Причина |
|---|---|---|
| UI | Flutter 3.47 (Material 3) | Один код и один внешний вид для Android и Windows |
| Состояние | Riverpod 3 | Модульность, лёгкая подмена зависимостей в тестах |
| Хранение | SQLite через `package:sqlite3` | Встроенный SQLite, транзакции, WAL, тесты на базе в памяти |
| Редактор | flutter_quill 11 | Формат Delta (JSON), чек-листы, Ctrl+B/I/U, undo/redo |
| Криптография | `cryptography` (чистый Dart) | X25519, HKDF-SHA256, ChaCha20-Poly1305, Argon2id |
| Ключи | flutter_secure_storage (Android), DPAPI (portable Windows) | Защищённое хранилище ОС |
| Сеть | `dart:io` (UDP + TCP) | Без нативного кода, работает на Android и Windows |
| QR | qr_flutter, mobile_scanner | Показ QR на ПК, сканирование на телефоне |
| Файлы | `file_picker` 13 | Выбор фото и файлов для вложений |

## Структура

```
lib/
  main.dart                     запуск, тема
  domain/                       чистые модели без Flutter
    note.dart                   Note + сериализация для передачи по сети
    attachment.dart             метаданные вложения
    version_vector.dart         векторы версий (сравнение, слияние)
    conflict.dart, peer.dart
  data/
    schema.dart                 миграции SQLite (PRAGMA user_version)
    note_store.dart             CRUD, журнал, поиск, важное, архив, вложения,
                                применение удалённых изменений, конфликты, настройки
  sync/                         чистый Dart, покрыт тестами
    transport/frame_channel.dart   кадры с префиксом длины поверх TCP
    crypto/keys.dart               идентичность устройства, хранилище ключей
    crypto/secure_channel.dart     рукопожатие и шифрованный канал
    discovery/lan_discovery.dart   UDP-маяки (multicast + broadcast)
    pairing/pairing.dart           QR-полезная нагрузка, одноразовые коды
    engine/sync_engine.dart        обмен изменениями заметок и метаданными вложений
    engine/file_transfer.dart      скачивание файла: чанки по 256 КБ, проверка SHA-256
    sync_service.dart              сервер, автосинхронизация, повторы, статусы
  ui/
    providers.dart              DI и состояние (Riverpod), настройки
    layout/  notes_list/  editor/  archive/  conflicts/  devices/  settings/
    attachments/                панель вложений, статус-точка, сервис файлов
test/
  data/      хранилище и миграции
  sync/      криптография, движок, сервис через настоящий TCP
  release/   проверка кодировки описаний релизов
```

Зависимости направлены внутрь: `ui → sync/data → domain`. Слой `sync` не
знает о Flutter, поэтому новый транспорт — это новая реализация `FrameChannel`.

## Модели данных (SQLite)

```sql
notes(
  id TEXT PK,             -- UUID v4
  title, content,         -- content = Quill Delta JSON
  plain, search,          -- текст для превью и поиска
  created, updated,       -- мс от эпохи
  vv TEXT,                -- вектор версий {"deviceId": counter}
  dev TEXT,               -- устройство, создавшее версию
  deleted INT,            -- метка удаления (tombstone)
  important INT,          -- важная заметка (сверху, синхронизируется)
  archived INT,           -- заметка в архиве (скрыта из основного списка)
  seq INT,                -- локальный номер изменения (курсор синхронизации)
  src TEXT,               -- от какого устройства получена версия
  dismissed TEXT          -- ключи отклонённых конфликтных версий
)
attachments(id PK, note_id, name, mime, size, sha256, created)
file_holders(sha256, device_id)     -- какие устройства держат файл на диске
saved_copies(sha256 PK, path)       -- путь к сохранённой копии файла
change_log(seq PK AUTOINCREMENT, note_id, op, vv, device, at)
conflicts(id, note_id, loser_key, payload, detected)
peers(device_id PK, name, public_key, paired, last_sync, addr, port, epoch, recv_cursor)
settings(key PK, value)
```

### Вложения

* Байты файла лежат на диске в `<данные>/attachments/<sha256>`, одинаковые
  файлы хранятся один раз.
* Метаданные вложения едут вместе с заметкой в поле `a` и применяются только
  при применении версии заметки.
* Скачивание идёт по отдельному режиму рукопожатия `fetch`: только для
  сопряжённых устройств, зашифровано, файл проверяется по SHA-256 до сохранения.
* Статус вложения: зелёный — файл на этом устройстве; красный — есть на
  другом устройстве; серый — нигде нет. Другие устройства сообщают, какие
  файлы у них на диске (`held` в начале сессии).

## Правила миграций

Миграции в `schema.dart` только добавляются в конец списка. Выпущенную
миграцию нельзя менять или переставлять: версии у пользователей сдвинутся.
Порядок 1.1.0–1.2.x зафиксирован тестом `test/data/migrate_test.dart`.
Перед обновлением схемы создаётся копия `notevibe.db.bak-vN`.

## Синхронизация и журнал

* Каждое локальное изменение выполняется одной транзакцией: обновляется
  заметка, к вектору версий добавляется `+1` для своего устройства,
  дописывается запись в `change_log`, назначается новый `seq`.
* После сессии синхронизации сервис проверяет журнал: если за время сессии
  была локальная правка, синхронизация запускается снова.
* База работает в режиме WAL, сбой или аварийное завершение не портят данные.
* Публичные ключи устройств дублируются в защищённом хранилище, поэтому
  подмена файла базы не позволит выдать себя за сопряжённое устройство.

## Автосохранение

Редактор сохраняет изменения через 500 мс после последнего нажатия, а также
при уходе со страницы, сворачивании или закрытии приложения.
