# Протокол синхронизации NoteVibe (v1)

## 1. Обнаружение

* UDP-порт **47800**, multicast-группа `239.77.88.99` плюс broadcast `255.255.255.255`.
* Каждые 3 с отправляется маяк `{"nv":1,"id":…,"name":…,"port":<tcp>,"fp":<отпечаток ключа>}`.
* Устройство, не присылавшее маяк 12 с, считается ушедшим из сети.
* Маяк не аутентифицирован: это только подсказка адреса. Подлинность устройства
  проверяется рукопожатием, поэтому поддельный маяк ничего не даёт.
* На Android удерживается `WifiManager.MulticastLock`, иначе система отбрасывает multicast-пакеты.
* Если multicast заблокирован роутером, IP-адрес можно указать вручную.
  Последний известный адрес также запоминается.

## 2. Транспорт

TCP, порт **47801** (если он занят, выбирается свободный и объявляется в маяке).
Кадр = 4 байта длины (big-endian) + данные, максимум 16 МБ.

## 3. Рукопожатие (по мотивам Noise KK/IK)

У каждого устройства есть статическая пара ключей X25519 (`s`). На каждый
сеанс создаётся эфемерная пара (`e`).

```
I → R : hello{v, mode, id, name, e_I, s_I}          (открыто)
R → I : hello{v, id, name, e_R, s_R} | error{code}  (открыто)
ikm   = DH(e_I,e_R) ‖ DH(s_I,e_R) ‖ DH(e_I,s_R)
k_I→R ‖ k_R→I = HKDF-SHA256(ikm, salt=SHA256(transcript), info="notevibe-v1"‖PSK)
I → R : AEAD{confirm} ;  R → I : AEAD{confirm}
```

* **sync** — обе стороны сверяют `s` собеседника с сохранённым ключом
  (константное время сравнения). Незнакомые устройства получают `unknown_peer`.
* **pairQr** — QR содержит `id`, публичный ключ, адреса, порт и 128-битный
  токен. Инициатор сверяет `s_R` с ключом из QR (защита от перехвата), а токен
  входит в PSK: без него подтверждение не пройдёт.
* **pairCode** — 6 цифр: `PSK = Argon2id(code, salt=SHA256(transcript))`.
  Пассивный наблюдатель код не узнает. Активный атакующий получает одну
  попытку на соединение, а после 3 неудачных попыток код аннулируется.
  Срок жизни кода и QR — 2 минуты, использовать их можно один раз.
* Сообщения шифруются ChaCha20-Poly1305 с отдельными ключами для каждого
  направления. Nonce — счётчик, поэтому повтор, подмена или изменение порядка
  кадров вызывают ошибку расшифровки и разрыв соединения.
* Защищённость сеанса: при компрометации долговременного ключа прошлые сеансы
  не раскрываются, потому что для каждого сеанса используются новые эфемерные ключи.

## 4. Обмен изменениями

```
I → R start{epoch}        R → I start{epoch}
R → I want{cursor}        -- фаза A: I отправляет свои изменения
I → R batch{notes,last,done}   R → I ack{last}   (повторяется)
I → R want{cursor}        -- фаза B: R отправляет свои изменения
R → I batch …             I → R ack …
I → R bye
```

* `cursor` — наибольший `seq` отправителя, который получатель уже **записал
  в базу**. Курсор хранится в `peers.recv_cursor` и обновляется **в той же
  транзакции**, что и применение пакета. Если связь оборвалась, следующий
  сеанс начнётся с последнего сохранённого пакета: ничего не потеряется и
  ничего не будет пропущено.
* В пакет попадает только последнее состояние каждой изменённой заметки (по 100 штук).
* Заметки, полученные от этого же собеседника (`src`), обратно не отправляются.
* `epoch` — случайный идентификатор базы. После переустановки приложения на
  другом устройстве курсоры сбрасываются и выполняется полная синхронизация.
* Повторное применение одного и того же пакета ничего не меняет.

## 5. Слияние

Для каждой входящей заметки `R` и локальной `L` сравниваются векторы версий:

| Сравнение | Действие |
|---|---|
| нет локальной | вставить `R` |
| `R ≤ L` | игнорировать (уже есть) |
| `L < R` | заменить на `R` |
| параллельные изменения, данные совпадают | слить векторы, конфликта нет |
| параллельные изменения, данные различаются | **конфликт** |

При конфликте выбирается детерминированный победитель: удаление проигрывает
правке, затем побеждает более поздний `updated`, при равенстве — больший
`deviceId`. Победитель с объединённым вектором становится текущей версией на
**всех** устройствах. Проигравшая версия сохраняется в `conflicts` (и тоже
передаётся другим устройствам), а пользователь видит статус «Конфликт».

Пользователь может:
* **Оставить текущую** версию,
* **Взять другую** версию,
* **Сохранить обе** — другая версия станет новой заметкой «… (копия конфликта)».

Решение записывается как новая версия (`vv = merge(vv_cur, vv_other) + 1`).
Ключ отклонённой версии добавляется в `dismissed` и передаётся вместе с
заметкой, поэтому копия конфликта удаляется на всех устройствах и больше не
появляется.

## 6. Статусы и автосинхронизация

* **Синхронизировано** — последний сеанс успешен, локальных изменений нет.
* **Синхронизация** — идёт сеанс или ожидается отложенная отправка.
* **Нет подключения** — нет сопряжённых устройств, они не в сети или последняя попытка не удалась.
* **Конфликт** — есть неразрешённые конфликты.

Когда запускается синхронизация (если она включена в настройках):
* при обнаружении сопряжённого устройства;
* через 2 с после локального изменения;
* раз в 30 с;
* при возвращении приложения на передний план.

При ошибке повтор откладывается на 5, 15, 30, 60, а затем 120 с.
Кнопка «Синхронизировать» работает всегда.
